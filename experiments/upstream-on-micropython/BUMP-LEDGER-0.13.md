# BUMP LEDGER — verbatim-upstream flavors, build123d 0.11.1 → 0.13.0

The deliverable of `feat/b123d-013-upstream`: every category of work the
0.11.1 → 0.13.0 bump forced on the two VERBATIM-upstream flavors, with
measured effort, so the next bump is priced.

- `pysrc=upstream` — build123d's own Python (Level-A + drafting +
  geometry.py + the whole topology package) on the custom micropython-cs
  interpreter over the OCP-over-embind shim (browser default for
  `?pyruntime=micropython`, and `cascade-headless-upstream`).
- `pysrc=real` — the unmodified PyPI wheel on Pyodide/CPython + real numpy
  over the same shim.

Target: build123d **0.13.0** (PyPI 2026-09-21, tag `v0.13.0` @ 38effd34) —
0.12's features (BuildScope + BaseObjectMeta construction firewall, StrEnum
`Unit`, build_constants/pack_utils split, bd_materials) plus the OCP/OCCT
8.0.1 port (PR gumyr/build123d#1442: `OCP.collections`, the kernel-record
`ShapeHistory` behind `Select.LAST/NEW`, convexity classification, ...).
Prior art: `feat/upstream-b123d-dev-bump` (dev@44a8d7c1 over the lite seam,
~6 h, BUMP-LEDGER.md on that branch). This bump is the first one with
upstream's TOPOLOGY running verbatim (Stage 3), so it also carries the OCP
surface delta.

Clock: started 2026-10-15 07:53 PDT.

## F. pytopo=lite retired — ~15 min

`?pytopo=lite` (upstream Level-A over a seam of lite's classes) could not
carry 0.13: build_common imports `ShapeHistory` from the topology package
and reads the kernel's own operation record for `Select.LAST/NEW`, and
publishes through the BuildScope firewall — neither of which lite's topology
models (porting the dev-bump's six seam fills would still leave Select.LAST
without a record). The flag parses, warns and runs upstream; the seam
modules (~1,170 lines: upstream-py/build123d/geometry.py + topology/*, the
dead Stage-2 constrained_bridge.py) and `_finalize`'s lite branches are
gone. The runtime now probes the ocp_shim payload AND interpreter
metaclasses before choosing pysrc=upstream (stock artifacts → pysrc=lite).

## I. Verdict

**A verbatim-upstream bump across a kernel-binding generation costs ~2 hours,
not days** — measured: 07:53 start → 08:09 first green node run on 0.13 →
08:38 first full harness (221) → 09:15 final numbers (233 / 232) → gates and
docs by ~09:25. Where the time went:

- ~15 min vendoring (one-time tooling was ported from the dev-bump branch;
  the next bump is `fetch --src --version` + one VENDOR_MODULES entry).
- ~35 min OCP surface: the bill/dump/generator pipeline re-ran cleanly
  against OCP 8.0.1 once it learned the `OCP.collections` aliasing; every
  new MISSING item was glue-able (no fork rebuild).
- ~30 min MicroPython friction — the expensive item of the dev bump
  (BaseObjectMeta emulation, ~1.5 h) is now ZERO thanks to the
  micropython-cs metaclass patches; the one surprise was the
  `_GenericMeta`/ABCMeta metaclass conflict (10 min).
- ~20 min deps (bd_materials REAL on Pyodide, honest stubs elsewhere).
- ~85 min harness grind + classification, nine S-sized fixes; the two
  biggest classes were the MEASUREMENT contract (0.12's local `_obj`) and
  new 0.13 API surface (export_obj/tessellate, import result shape,
  anytree.path).
- ~15 min retiring pytopo=lite (it could not carry 0.13 at any reasonable
  price; deleting ~1,170 seam lines was cheaper than porting them).

Price the next bump at **~2 h + ~10 min per new kernel-facing feature**, more
only if upstream adopts a CPython construct MicroPython cannot express (a
new metaclass protocol, `__class_getitem__`-only generics, `__init_subclass__`)
— those are interpreter patches, not shim work.
